## Brief
Symptom: scrolling up into scrollback and holding, the window below the viewport keeps streaming — the anchored row drifts as the tail advances. Mechanism (scout-verified): crates/kampr-tui/src/render/fit.rs place (188-215) treats scroll as an offset FROM THE TAIL: bottom = total - scroll, total = history + need.rows. There is no follow/lock flag; when the surface grows while scroll > 0, bottom and top both grow, so the whole window shifts down by the number of new rows. Fix: remember the previous total per pane in the TUI scroll state; when total grows while scroll > 0, add the delta to scroll so the window stays pinned (chrome.rs:422-431 render path already recomputes placement and writes back the clamped scroll each frame — the natural place). Scrolling down (scroll/act.rs:921-933, wheel/mod.rs:426-446) then pages through the rest of the history; at scroll == 0 the tail is reached and following resumes. PanReset (act.rs:474-479) and the caret rule (caret only at scroll == 0, chrome.rs:473) stay as they are. TDD: integration-level — a pane with a growing grid while scroll > 0 keeps the row under the eye fixed; scrolling down reaches the tail and following resumes; a fresh pane (scroll == 0) still follows the tail. Prove load-bearing: reverting the fix fails the tests. House rules: zero comments by default; allocation-free render paths are required (no per-frame allocation); #NNN are probe-log citations.
